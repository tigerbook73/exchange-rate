# Vite + React + Cloudflare Workers 重构计划

创建日期：2026-11-23。执行状态见[进展文档](../progress/vite-react-workers-migration.md)。本文只维护目标、范围、阶段和验收标准；日常结果与证据记入进展文档。

## 1. 目标与边界

先整理架构文档与流程规范，再以 Vite + React 和原生 Cloudflare Workers 替换 Next.js + OpenNext，降低构建、运行时适配和日常维护负担。

- 保留单仓库、网站 Worker、独立采集 Worker 和现有 D1；网站通过 Static Assets 提供前端，通过同源 `/api/*` 提供只读查询。
- 保留 React、TypeScript、pnpm、Base UI、Tailwind、Chart.js、IndexedDB 和 Serwist；Serwist 改用 Vite 集成，继续复用对应的 `defaultCache`。
- 保留现有业务规则、API 路径与协议、游标、数据库身份及离线数据；本次不以框架迁移为由清库、重置 revision 或提升 API schema。
- 本次不重做图表交互、同步协议、D1 结构或采集算法，不新增 KV、Queues、Durable Objects，不合并采集与网站 Worker，不引入前端路由库。
- 业务规则以整理后的[技术方案](../blueprint.md)为主；本文不复制分钟归属、固定点、缺日、历史校准和保留策略。
- 当前代码仍为 Next.js + OpenNext；目标架构在对应阶段完成前不能写成已实现。用户已要求开始实施；执行遵循有效的操作授权，`git push` 仍需明确授权。

## 3. 第二阶段：模块边界整理

在现有应用仍可运行的前提下整理依赖方向，测试随源文件移动，不改变业务语义。

建议目标目录：

```text
src/
  main.tsx
  App.tsx
  components/            # 保留 ui/ 基础组件
  lib/
    domain/              # 纯业务规则，不依赖存储或框架
    contracts/           # API 协议与共享领域类型
    client/              # IndexedDB、同步、升级、React hooks
    server/              # D1、采集、历史校准
  sw/                    # 浏览器 Service Worker
worker/                  # 网站 API 入口
collector/               # 独立 Cron 入口
public/                  # manifest、图标、字体等
scripts/
migrations/
e2e/
```

- 将 `RateRecord` 等共享类型从 IndexedDB 模块提取，消除服务端对客户端模块的类型依赖。
- 领域模块不导入客户端、服务端或框架；前端不导入 D1 与采集实现；Cron 不导入历史 HTML 解析依赖。
- 区分浏览器、网站 Worker、SW、collector 和 Node 管理脚本的类型及运行环境；binding 类型继续由 Wrangler 生成。
- 保留所有已应用 migrations；不为目录整理增加数据库迁移。

验收：类型检查、相关单测与 D1 集成测试通过；旧应用仍可运行；没有协议、数据库或领域行为变化。必要时用轻量导入约束防止环境依赖倒置，不增加新的工程管理框架。

## 4. 第三阶段：替换构建与网站入口

1. 使用 Vite、React 插件和 Cloudflare Vite 插件建立入口，保留现有组件和页面行为。实施时核对官方文档及依赖兼容性，使用适配的稳定版本。
2. 将 Route Handlers 迁为 Worker 请求处理，直接接收 D1 binding；保留参数校验、响应结构、状态码、缓存语义及查询不触发采集的约束。
3. 配置 Static Assets 与 `/api/*` 路由优先级；未知 API 返回明确错误，不被 SPA 回退转成 HTML。保留完整游标缓存键，不仅凭响应头宣称缓存命中。
4. 将 metadata、亮暗主题色、manifest、图标和字体接入 HTML 与新入口；保留系统主题和移动布局，不添加主题切换功能。
5. 调整开发、构建、本地数据管理、类型生成和部署命令；本地开发与 preview 不访问生产 D1。
6. 完成替换后移除 Next.js、OpenNext、相关 ESLint 配置、旧入口、失效脚本及环境变量引用；按实际依赖判断是否仍需网站 `nodejs_compat`。
7. 从目标网站配置移除不再使用的框架 R2、自引用和图片绑定；云端资源先保留供回退，不随配置清理自动删除。

验收：格式、lint、各运行环境类型检查、单测、D1 集成测试、Chromium 页面 E2E、新网站生产构建及两个 Worker 打包检查通过；本地真实 Worker API 行为正确。完成替换后不再要求旧 Next.js/OpenNext 构建。更新测试入口与 mock，保留只读查询的零上游调用断言。

## 5. 第四阶段：PWA 兼容与发布准备

- 使用 `@serwist/vite` 接入构建与注册；核对其 `defaultCache` 与现有需求，验证 API 缓存和导航离线行为，排除 `/_headers`、`/_redirects` 等配置文件。
- 保持域名、`/sw.js`、scope、安装入口身份和 IndexedDB 身份稳定；保持现有 API schema、datasetId 与游标，不因更换框架清空客户端数据。
- 分别验证新安装、旧 Next.js PWA 在线升级、已打开旧标签页、断网重载、恢复联网及后续新版到新版更新。
- 重点覆盖旧 SW 缓存页面及 `/_next/` 资源向 Vite 资源的交接；普通错误不清缓存，不通过注销全部 SW、清空 IndexedDB 或删除全部资源缓存解决更新问题。
- 保留已有数据的同步中展示、系统亮暗主题、前后台轮询与图表恢复尺寸。
- 检查统一发布入口、生产资源绑定及 CI 覆盖变量隔离；保留迁移和初始化先于发布的顺序，失败停止发布。通用 build 不连接生产。

验收：生产模式本地预览完成 SW 接管和离线重载；使用旧版本产物与同源浏览器配置验证实际升级，不以全新上下文测试代替。记录操作和结果；与开发服务或构建争用产物的验证分开执行。发布前形成可执行的切换及回退步骤。

## 6. 第五阶段：生产切换

在授权范围内执行；本计划存在本身不表示已部署。

1. 核实线上版本、D1 状态、可恢复备份和网站/collector 回退版本；核对全部 migrations 的实际应用状态及其与旧版本的兼容性。
2. 核实 Cloudflare Builds 的生产分支、命令及令牌权限；核实仍可能影响发布的 Vercel 自动部署，不能把旧记录中的权限失败视为已解决。
3. 生产迁移与初始化 → 检查数据就绪 → 发布 collector → 验证采集 → 发布网站 → 验证 API、页面和旧 PWA 升级。维持网站 Worker 名称与自定义域名，避免跨源丢失离线数据。
4. 分别记录网站请求与 Cron 的 CPU、D1 读写、构建耗时、资源体积和缓存行为；尽可能与同环境基线比较，不把框架精简当作免费额度达标的证据。
5. 失败时回退到已记录且兼容当前 D1 的只读网站版本；如需回退 collector，单独核对写入兼容性。不自动回滚数据库或清库，保留回退所需资源。
6. 记录实际发布状态与仍待观察的事项，作为最终文档整理的依据。稳定后再单独判断云端旧资源删除时机；不因迁移完成自动删除 R2 桶或历史部署。

验收：线上查询不触发源站抓取，采集和历史数据连续，旧客户端及旧 PWA 能继续使用或正常更新；本地、推送、部署与线上验证状态分别记录。未完成的长期观察继续保留，不阻塞与其无关的已验收阶段，也不能标成通过。

## 7. 第六阶段：最终文档整理、简化与清理

在重构验收及生产切换后，以最终实现和实际验证结果为准进行一次完整文档收尾；本阶段完成后才视为重构收尾完成。与第一阶段的区别是：第一阶段降低迁移前的维护负担，本阶段移除迁移期间留下的过渡内容。

1. 逐一核对 README、AGENTS、CLAUDE、blueprint、phase-workflow，以及配置和脚本旁的操作说明；架构图、目录、依赖、命令、类型环境、测试和部署步骤必须对应最终实现。
2. 删除失效的 Next.js/OpenNext、webpack、旧入口与旧路径说明，以及迁移期间的双栈操作、临时兼容指引和已撤销方案；仍在使用的兼容行为与回退资源只保留必要说明，不误删其有效操作依据。
3. 再次合并重复规则，每项保留一个主要说明位置；精简 AGENTS 和通用流程，移除重复验收清单、已解决故障过程及历史授权叙述中的过时状态，保留有效权限边界。
4. 将长期结论归入 blueprint，操作归入 README，开发约束归入 AGENTS；把尚未完成的观察或问题集中到一个明确的当前待办位置，保留状态、后续动作及必要证据，不伪装成已完成。
5. 核对本计划、本次进展及旧阶段文档的信息已完整归位后，按项目收尾规范删除已完成的计划和临时记录；不另建重复历史归档或阶段索引。Git 历史保留过程，需要继续使用的回退依据和证据不得随过程记录一起丢失。
6. 清理已删除文件的入口和交叉引用，检查相对链接、命令名称、文件路径和格式；复查剩余文档是否仍把目标描述为待迁移，或把本地结果描述为线上结果。

验收：从 README 能直接找到当前架构、开发规范、运行部署方式和未完成事项；无断链、失效命令、重复规则、无用途临时文档及过时技术栈指令；必要的业务规则、数据保护、权限、兼容及回退依据完整保留。纯文档变更检查格式、链接和一致性，不重复运行无关应用测试。文档收尾单独提交，不混入代码功能修改。
