# 工商银行澳币汇率 PWA — 技术方案

本文件描述当前本地实现。无租约采集及部署前兼容检查尚未发布，线上仍为优化前版本。服务端采集、官方现价 API 与部署前历史同步基线已于 2026-11-22 部署至 Cloudflare：网站 `icbc-rate`、采集 `icbc-rate-collector`、D1 `icbc-rate`，正式入口为 https://icbc-rate.tigerbook.top 。实时验证及仍需观察的额度、缓存效果见 [进度](progress/cloudflare-server-rates.md)，操作见 [README](../README.md)。

## 1. 架构

```text
每分钟 Cron → 独立采集 Worker → 工商银行 JSON API → 校验 → D1
部署前 Node.js → 快易理财历史页 → 历史校准 → D1
                                                        ↑
浏览器 / PWA → Next.js + OpenNext 网站 Worker → 只读查询 ┘
    ├─ IndexedDB：每日历史、固定点、一个临时点、同步游标
    └─ Serwist：静态资源与离线响应缓存

OpenNext R2 增量缓存：仅用于框架缓存，不作业务历史存储
```

- 仅 Cloudflare 部署，不再维护 Vercel 部署兼容性。保留 Next.js 16、OpenNext、webpack、Serwist、Chart.js 与 Base UI。
- 网站请求、缓存失效和空库不会触发源站抓取。未初始化时 `/api/sync` 返回 503，客户端保留本地数据。
- 服务端是业务数据权威；客户端是可重建的离线副本，不上传报价。
- 本地通过显式命令初始化 / 采集；`collector:local` 每分钟运行同一采集逻辑。真实云端由独立 Worker 的 `scheduled()` 执行。采集 Worker 只用原生 Web API，不启用 `nodejs_compat`；网站 Worker 继续保留 OpenNext 所需兼容层。

## 2. 数据源和解析

现价直接读取工商银行 JSON，历史校准在部署前本机 / CI 中使用 `cheerio/slim`；独立采集 Worker 不导入历史 HTML 解析依赖。旧现价实现 `fetchLegacyToday` / `parseTodayHtml` 保留，当前没有调用或自动回退。

- 现价源：`http://papi.icbc.com.cn/exchanges/ns/getLatest`，POST 空 body，带用户提供的 Content-Type、Referer、User-Agent；只读取唯一 `AUD` / `029` 的 `foreignSell`。[官方牌价页](https://www.icbc.com.cn/forex/foreignEx/forex.html)口径为人民币 / 100 外币，转换成每澳元万分之一单位整数，按十进制正确舍入。
- 官方完整 `publishDate` + `publishTime` 按 UTC+8 组成秒级 `publishedAt`，无需推断年份。校验响应 code、币种唯一性、正数价格及真实日历 / 时间；失败保留上次报价，不换用现金价或旧源。
- 历史源仍为 `https://www.kylc.com/huilv/d-icbc-aud.html?datefrom=YYYY-MM-DD`。读取逐日表，不读取汇总表；初始回溯 365 天。
- 源站请求 8 秒超时；官方 JSON 限制 64KiB，历史 HTML 限制 1MiB。当前按用户提供的 HTTP 入口试用；HTTPS 本机探测出现旧 TLS 重协商错误，没有关闭证书验证来绕过。
- 旧网页源 URL 及解析函数保持可用，仅用于显式比较，其缺年份的跨年规则仍保留。测试使用本地 JSON / HTML fixture，不请求源站。

## 3. 时间归属与固定点

- 所有业务日期按北京时间 `Asia/Shanghai` / UTC+8；官方报价使用完整日期和秒级时间。旧网页源的缺年份与跨年规则仅在显式使用旧实现时生效。
- `scheduledAt` 是 Cron 计划时间；业务归属以源站请求实际 `requestedAt` 截断到分钟为准。`receivedAt`、`publishedAt` 分别保存返回完成时间和源站发布时间，不替代采集归属。
- 10:05:05 发起算 10:05；10:05:59 发起、10:06:03 返回仍算 10:05，超时规则保持不变。
- 每分钟采集，固定保留整 5 分钟 `:00、:05、:10……` 的点；10:01～10:04 只覆盖一个临时点。到 10:05 固定保存后清空上一临时点，10:06 再产生新临时点。
- 固定点 T 失败或漏触发时，可以取 `[T−5 分钟,T]` 内最近真实成功采集的值。保留 `sourceMinute`、`sourceRequestedAt`、`isFallback`，UI 标出来源；不能把回退值继续当作真实采样沿用。
- 无符合条件的真实值则固定点缺失，图表断线。未来报价不能倒填过去点。漏掉固定分钟的 Cron，在后续覆盖真实成功状态前处理可回退的旧边界。
- 固定点直接成功、回退或缺失后，均清空其之前的临时点。卡片可以显示更旧的最后已知报价，但须显示来源时间。
- 前一天报价 / 午夜跨日回退可显示，须标旧报价，不作为新一天的真实每日历史。

## 4. 持久化与写入一致性

D1 migrations 位于 `migrations/`：

| 表                 | 用途                                                                          |
| ------------------ | ----------------------------------------------------------------------------- |
| `collection_state` | 数据集 ID、版本、最早有效游标、唯一临时点、最近真实值、任务游标和批次写入标记 |
| `intraday_points`  | 按整 5 分钟时间键保存真实 / 回退 / 缺失固定点                                 |
| `daily_rates`      | 每日真实、暂定、明确标记的沿用历史                                            |
| `collection_runs`  | 保留旧版诊断供过期清理；新版不再逐轮写入，使用结构化日志                      |
| `sync_changes`     | 有序版本、实体键、删除标记，不保存临时价格历史                                |

- 每次采集只读取一次状态；已处理的分钟直接跳过。取消租约申请 / 释放及独立运行时版本检查，正常完整轮次只做一次读取和一次 D1 batch；偶发并发可能重复抓源站，但提交按分钟幂等。
- 固定点、临时点、每日暂定值、版本和变更标记通过 D1 batch 原子提交。条件更新检查旧 revision 与采集分钟，随机 `write_id` 只标识本批是否获准写入，不是锁，不需超时或释放；失败批次不能借用赢家 revision 写入实体或同步标记。遇到冲突可跳过，不密集重试。
- 同一源站报价（发布时间与价格都未变）不重复写每日值及其变更标记；仍更新分钟采集状态。
- 批量点使用 `json_each` 写入，不为一年初始化生成数百个单独数据库调用。
- 查询通过单条 SQL 读取元数据、当前实体及删除信息，确保数据与游标来自同一读快照。
- 价格和状态检查独立：源站未改报价不代表采集失败；源站时间异常倒退不得覆盖更可信的最新报价。

## 5. 保留与清理

| 数据           | 策略                                               |
| -------------- | -------------------------------------------------- |
| 固定点         | 北京时间今天与前两天，最多约 864 个固定分钟        |
| 临时点         | 每币种最多一个，成功采集后覆盖，不积累完整分钟历史 |
| 每日历史       | 长期保留，暂不自动过期，默认 UI 查看最近一年       |
| 旧版 D1 诊断   | 30 天；新版任务诊断仅写结构化日志                  |
| 同步变更元数据 | 3 天，超期游标需有限范围重建                       |

每 15 分钟的采集轮次之后有界清理过期固定点、诊断与变更记录；正常调度下物理删除可能滞后约 15 分钟。清理失败记录后重试，不回滚已成功采集。查询先按逻辑保留范围过滤，不能因物理清理滞后继续暴露过期固定点。临时点过期后不作为有效当前周期点返回，最近真实值独立保留供卡片显示。

清理固定点不会删除 `daily_rates`。诊断和同步日志不记录每次临时价格 payload，避免借日志重新积累分钟历史。

## 6. 每日历史校准

- 使用独立历史游标，不从当天采样最大日期推算。起点为最后确认历史日期本身与最早未校准暂定日期中的较早者；初始化默认为今天前 365 天。
- 通过 `pnpm run deploy` / `pnpm run deploy:collector` 在发布前由本机 / CI 的 Node.js 执行；不在 Next 构建中抓取、不占 Cron Worker CPU。提交冲突有限重试，未成功更新或历史源失败则停止发布。日常 Cron 不再触发历史校准；长期不部署的历史漏采 / 修正留待下次部署或显式回填。
- 过滤 history 中今天及未来记录，当天只信真实采集源。每日暂定值独立保存，随后由历史真实值确认。
- 缺日范围扩展至北京时间昨天，不再受历史源返回的最后日期限制，不硬编码周末。引用此前最近的真实 / 暂定日期，标记 `source: "carried-forward"` 与 `carriedFromDate`，不连续沿用填补记录、不向前倒填、不补今天。标记仅表示沿用已知报价，不能据此认定源站当天未发布报价。
- 每日首次成功提交的分钟批次中补齐尾部缺日，即使本次源站失败或仍返回旧日报价也执行。`dailyFilledThrough` 与实体共用 revision / write_id 原子提交；冲突或回滚不推进标记，下一轮重试。当天后续轮次不重复补缺。最近真实日记录按需合入原有状态 SELECT，不增加 D1 往返。
- 显式 `pnpm db:repair-gaps` / `pnpm db:repair-gaps:remote` 使用现存每日记录修复内部与尾部缺日，无源站请求，不推进历史确认游标、不清库；后者显式访问生产。部署前历史校准合并真实数据后执行相同补缺，并重新计算受历史修正影响的沿用值。
- 已有真实或暂定记录不能因历史一次省略该日就被无提示覆盖为沿用值；未确认暂定日期继续等待后续校准。

## 7. 查询 API 与同步

所有 API 均只读 D1，无源站抓取或业务写入路径：

| 路径                                      | 用途                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| `/api/sync`                               | 首次有限快照：最近一年每日历史、三日固定点、一个临时点及状态                     |
| `/api/sync?cursor=<datasetId>.<revision>` | 仅返回版本之后改变的实体当前值；临时点不逐分钟回放                               |
| `/api/intraday?date=YYYY-MM-DD`           | 三日内指定日期固定点与适用的临时点，过期日期返回 410                             |
| `/api/today`                              | 兼容原报价 JSON，来自最近真实成功采集                                            |
| `/api/history?datefrom=YYYY-MM-DD`        | 兼容原 JSON，返回默认一年窗口内的真实 / 暂定日值，省略沿用值以免旧客户端误认真实 |

同步返回 schema、数据集身份、游标、生成时间、保留起点、历史窗口起点、每日实体、固定点、删除项与状态。正常增量一般只有临时点 / 状态，每 5 分钟多一个固定点；历史修订同样同步。临时点在本地使用同一逻辑键，固定时清空，不遗留旧分钟点。

游标错误、超出最早有效版本或数据集重建时返回 409 `resetRequired`；App 再取有限快照。正常轮询不会重复下载三日或一年全量。空库 / 数据库故障返回 503 且 `no-store`；已存报价在采集失败时保留。

当前版本 UI 仅使用默认一年历史窗口，更早历史仍保存在数据库；额外历史范围接口属于后续扩展，不承诺兼容接口已支持任意旧范围。

## 8. 缓存、新鲜度与离线

- 查询目标共享缓存 15 秒，并允许最多额外 15 秒陈旧响应；带完整游标的 URL 必须参与缓存键。动态 Route Handler 不凭 `revalidate` 声称已获得 ISR；线上命中仍待验证。
- IndexedDB `fx-cache` 升级为 v2：保留旧 `rates`，新增 `points` 和 `server` 元数据；旧版缓存先展示，成功快照后按权威窗口替换。
- 单次增量、保留边界与新游标在一个 IndexedDB 事务中提交。拒绝旧版本、同版本更旧快照或不同数据集的 delta；失败保留原游标及离线数据。
- 页面可见且在线时每 60 秒同步；打开、返回前台、恢复网络和手动刷新立即尝试；同一时间只运行一次。隐藏和离线不轮询。
- 服务端过期不主动擦除离线设备；成功联网同步后才清理本地三日前固定点，每日历史不随之删除。
- PWA 使用 `@serwist/next` 和 `defaultCache`。`/_headers`、`/_redirects` 是 Cloudflare 配置文件，排除预缓存；否则 404 会中止 SW 安装。
- `defaultCache` 同源 API 为 NetworkFirst。离线缓存响应也可能 HTTP 200，不能据此认定刚联网；UI 根据采集时间显示新鲜度，连续约三分钟无成功检查显示延迟。
- SW 在开发模式禁用。离线重载用生产本地预览验证：先在线加载、确认接管、在线重载一次，再断网重载。首次从未在线加载的设备不保证可离线使用。

### 协议升级与清理边界

- `/api/sync?schema=1` 声明客户端 API 版本；不匹配时返回 426 `client_upgrade_required` 和目标 schema，`no-store`。报价 revision 改变不表示 API 升级。
- 在线、可见客户端自动刷新一次，sessionStorage 保存目标版本防循环；刷新仍不兼容时保留缓存并提示重新打开。没有这套代码的旧 App 仍需要首次在线手动刷新。
- 新版接口兼容后获取合法 snapshot，原子清空旧 IndexedDB 数据并写入新窗口；下载或校验失败不清空。只清旧 API 响应缓存，新版静态资源和 SW 保留。
- D1 数据集 ID 改变时，以新快照重建本地副本；同一 schema 下不反复刷新页面。旧标签页不能将更高 schema 的本地缓存写回低版本。
- D1 独立保存 `schema_version`（结构代次，当前为 1），仅显式本地检查及部署前 preflight 校验，同时检查必需的 `write_id` 字段；API / Cron 不再逐次比较结构代次。实际 SQL / 数据错误仍返回未就绪或任务失败，不自动删库。统一部署先应用 migration 再做兼容性 / 数据就绪检查；失败停止发布，无法迁移时备份并显式切换新库。

## 9. 界面

- “1 日”仅查看当日分时；源站 `publishedAt` 的北京时间日期仍是旧日期时，自动显示最近有效报价日，并在卡片与图表标出完整日期，不提供三日选择。三日存储只作预备。源站同日价格未变仍有效，不硬编码开盘或休市时间。
- 今日采到但发布于前一日的报价不画成今日有效点；回退图表只使用那个日期实际采到的有效点，不把今天的观察倒填过去。最近有效日超过三日保留期时，报价卡片仍可显示，分时图提示过期并引导查看每日历史。
- 使用统一时间范围选择器：默认“30 天”为每日历史，“1 日”为分时，其余 7 天、90 天、半年、一年也为每日历史，不设置单独的“日内走势 / 每日历史”切换。
- 正常状态不显示服务端检查时间。报价日期早于今天时，在“更新于……”后标明“今天无更新”；当天报价发布时间落后服务端最近检查时间至少 5 分钟时，显示“当前无更新”，不以价格是否变化判断。不再单独展示“尚无今日有效报价……”警告、本地演示或采集延迟提示；离线、等待服务端数据和同步错误仍保留。页脚为“数据来自快易理财网及工商银行网站。仅供参考。”
- “1 日”裁掉首尾无有效数据的时段，标题显示“日期 开始时间–结束时间”；中间缺口按前一有效采集值显示并在 tooltip 注明。开头添加前一有效日末值的短水平参考线，来源日期明确、无数据点圆圈；无当日有效采样时不单凭前日末值造出走势。参考线和显示层沿用均不写入 D1 / IndexedDB，不修改服务器缺失状态或 5 分钟回退上限。
- 图表交互竖线使用单个独立覆盖元素，随触摸 / 鼠标当前选中位置移动，避免在画布上反复描线产生残留；线宽 2px，亮色使用半透明深灰，暗色使用半透明橘黄色。
- 时间范围单行横向滚动，支持触摸滑动和左右按钮；按滚动边界隐藏箭头，避免选项换行挤占画布高度。
- 回退点不再单独显示空心标记，沿用信息保留在来源 tooltip。每日历史无法补齐的缺失仍断线；分时图仅在显示层将时段内部缺口沿用前一个有效采集值，保留实际来源时间且不形成新的采集来源。最新临时点用实际发起分钟，固定点用固定分钟。
- 系统亮暗主题、同步时保留卡片结构和已有价格，在数字后以接近数字高度的旋转图标表示刷新，不在更新时间后显示加载文字、手机返回前台的主动画布 resize 均保留。
- 演示数据显式提示“非真实报价”，演示库拒绝混入真实采集。

## 10. 构建、测试与待验证项

- `dev` / `build` 保留 `--webpack`。Cloudflare 本地上下文只在开发阶段初始化，生产构建不启动本地 Wrangler。
- SW 和采集 Worker 独立 tsconfig；通过配置生成两套 binding 类型，不手写复制 Env。
- Vitest 覆盖日期、解析、固定 / 临时点、回退、事务、重复 / 迟到批次、部署前兼容检查、游标、清理和本地缓存。D1 集成测试使用真实本地模拟器及 HTML fixture。
- Playwright 用例 mock 查询 API，验证主题、历史范围、增量刷新、唤醒合并、前台轮询、旧缓存迁移与离线保留。生产 SW 验收单独检查受控后的导航缓存和断网重载。
- 云端 Cron 可靠性、运行 CPU / D1 / R2 额度、实际 CDN 命中和采集窗口观察尚未验证。当前保持全天采集，不硬编码周末休市。
- 用户要求在实际 Cloudflare 部署前暂停。未创建远程资源、未上传或部署、未推送 GitHub，也未停止 Vercel 后台自动部署；这些均留待用户审阅本地实现后再处理。
