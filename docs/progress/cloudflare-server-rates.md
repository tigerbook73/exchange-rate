# Cloudflare 服务端采集实现进度

### 2026-11-23 每日缺日补齐至昨天（本地）

- 用户确认将每日补缺范围从历史源实际返回区间扩大至北京时间昨天；不等待新日期报价，今天不生成沿用记录，不向前倒填。每日首个成功提交的分钟批次根据最近已存真实 / 暂定日值补齐尾部，即使源站失败或仍发布旧日报价也执行；沿用值直接指向真实来源日，不构成新的采集成功或历史确认。
- `dailyFilledThrough` 加入已有 state JSON，与补缺实体在同一 revision / write_id 批次中提交；无 D1 migration、API schema 或绑定变更。状态 SELECT 仅在需要跨日维护时按需读取一个最近真实日记录，分钟任务仍为一次读和一次 batch，既有每 15 分钟清理另计。冲突、回滚不推进标记；当天后续分钟不重复补缺。
- 每日 upsert 禁止沿用值覆盖已有真实 / 暂定报价，未变化的沿用值不重写；同步变更只记录本批次实际写入的日记录。真实历史校准合并已有记录后修复内部与尾部缺日，并重新计算受真实修正影响的后续沿用值；修复不推进历史确认游标。历史日值读取前取得 revision，后续并发写入会使整个旧批次失败，避免把旧日值和新元数据拼接提交。
- 新增 `pnpm db:repair-gaps`（本地）及 `pnpm db:repair-gaps:remote`（显式生产），仅使用现存日记录，不访问源站、不清库；重复运行无日值变化时不增加 revision。远程修复允许现价暂不可用，不将修复误当成部署就绪。统一部署前历史校准也包含补缺。
