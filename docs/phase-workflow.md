# 分阶段开发工作流

日常修复和小改无需创建阶段文档。跨阶段工作使用 `docs/plans/<slug>.md` 和 `docs/progress/<slug>.md`，当前入口见 README。

## 执行

- 计划维护目标、范围、排除项、阶段和验收；只有范围或方案变化时更新。进展维护状态、待办及验证证据，不写重复流水账。
- 先核对 AGENTS 和技术方案；已授权范围自主执行。新增服务、破坏性操作或突破未授权边界时先确认，现有授权不重复申请。
- 阶段范围内可创建 Conventional Commits；每阶段结束复核后续顺序。日常非阶段改动仅在用户要求时提交；git push 需要明确授权。

## 按变更范围验收

| 变更                 | 必要验证                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 纯文档               | 格式、相对链接、命令与实现一致性、diff                                                                 |
| 类型、模块或业务逻辑 | 类型检查、lint、相关单测；D1 行为改变时跑集成测试                                                      |
| 用户可见行为         | 相关 Chromium E2E，检查亮暗主题及自动化未覆盖的视觉效果                                                |
| 框架、构建或部署     | 完整类型、单测、页面 E2E、目标平台生产构建和两个 Worker 打包；PWA 另验真实 SW 接管、离线重载及旧版升级 |

- 命令以 README 为准，验证当前技术栈的目标平台构建，不维护已退役框架的检查。
- 测试不能请求真实源站；本地 D1 与生产隔离。生产模式 PWA 验证不得用禁用 SW 的开发服务替代。
- 未通过的验收继续处理；线上观察留为待办，本地结果不冒充部署结果。不为完成摘要而自行改变用户限定的发布范围。

## 收尾

- 长期结论归技术方案，操作归 README，开发约束归 AGENTS；每项保留一个主要说明位置。
- 未完成事项保留唯一当前入口。确认规则、证据和回退依据归位后删除已完成计划、临时进展和过时过程说明，Git 历史保留过程，不建重复历史索引。
- 文档收尾单独提交，不混入功能修改；检查删除文档的所有引用。
