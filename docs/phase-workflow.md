# 分阶段开发工作流

仅在开始或收尾一个需要分阶段交付的功能时使用；日常修复、文档整理和小改动无需建立阶段计划。

## 开始与执行

- 在 `docs/plans/phase-N-<slug>.md` 记录目标、范围、排除项、任务、测试计划和验收标准；目录不存在时按需创建。
- 先核对 [技术方案](blueprint.md) 与 [AGENTS](../AGENTS.md) 的架构边界；涉及突破边界、破坏性操作或新外部服务时先取得用户授权。
- 计划范围内可自主执行和创建逻辑清晰的 Conventional Commits；保持任务进度，不依赖某一种 Agent 专属任务工具。
- 每个阶段结束时复核剩余阶段的顺序与范围，按新发现调整计划。

## 验收

- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过；新增领域逻辑有对应单测。
- 修改用户可见路径时更新并运行 `pnpm test:e2e`，手动检查亮/暗主题及自动断言未覆盖的视觉效果。
- 部署配置变更还需验证目标平台构建与预检；两平台兼容要求同时验证标准 Next.js 与 OpenNext 构建。
- 逐条核对计划验收标准，未达成时继续处理，不用完成摘要代替验证。

## 收尾与文档保留

- 长期架构和接口结论更新到 `blueprint.md`，操作方式更新到 README，易错约束更新到 AGENTS；每项保留一个主要说明位置，其他地方链接引用。
- 删除已完成、内容已迁移的阶段计划和临时过程记录，不维护重复的历史阶段索引；提交历史负责保留过程。
- 阶段收尾文档整理单独提交，例如 `docs(scope): consolidate phase N docs`。
- `git push` 需要用户明确授权；日常非阶段改动的提交规则见 AGENTS。
